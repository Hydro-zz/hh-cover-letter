# AGENTS.md

Соглашения для ИИ-агентов (и людей), которые правят этот репозиторий. Прочитайте перед изменениями: здесь есть
правила, нарушение которых ломает релиз, приватность или работу расширения на hh.ru.

## Что это за проект

Расширение Chrome (Manifest V3) для hh.ru: на странице вакансии читает её текст и резюме пользователя, просит
языковую модель написать сопроводительное письмо и вставляет текст в форму отклика. Отклик **никогда** не отправляется
автоматически.

Пользовательские строки — русские. Идентификаторы в коде — английские. Комментарии только там, где логика неочевидна.

## Команды

```powershell
npm install            # один раз: нужен только для проверок (jsdom)
npm test               # проверки разбора страниц hh.ru
.\package.ps1          # сборка релиза в dist/hh-cover-letter-<версия>.zip
.\package.ps1 -Verbose # то же, со списком файлов архива
```

Расширение подключается как распакованное: `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное
расширение». Сборщика нет: исходники и есть готовое расширение, транспиляции не требуется.

## Структура

| Файл | Ответственность |
| --- | --- |
| `manifest.json` | Права, точка входа service worker, контент-скрипт, команда `Alt+Shift+C`, закреплённый идентификатор |
| `lib.js` | Каталог провайдеров, настройки по умолчанию, хранение, разбор ссылок, сборка промпта. Чистые функции без `chrome` |
| `background.js` | Service worker: запросы к провайдеру со стримингом, обработчики сообщений, чтение страниц hh.ru через вкладки |
| `content.js` | Панель на странице вакансии в shadow DOM, чтение вакансии, вставка письма в форму отклика |
| `options.html` / `options.js` | Страница настроек: провайдер, ключ, модель, стиль, источник резюме, имя, диагностика |
| `popup.html` / `popup.js` | Мини-панель на иконке: состояние готовности и быстрый запуск |
| `package.ps1` | Сборка релизного ZIP со всеми проверками |
| `test/extract.test.cjs` | Проверки разбора разметки hh.ru на jsdom |
| `store/` | Тексты витрины, обоснование разрешений, чек-лист публикации |
| `PRIVACY.md`, `CHANGELOG.md`, `LICENSE` | Политика конфиденциальности (RU+EN), история версий, MIT |

## Инварианты

### Релиз и версии

- Версия манифеста неизменяема после публикации в сторе: только вверх. Порядок выпуска — изменить код → поднять
  `version` в `manifest.json` → добавить запись с тем же номером в `CHANGELOG.md` → `.\package.ps1` → загрузить архив.
- `package.ps1` **вырезает поле `key`** из релизного манифеста. В магазине идентификатор выдаёт Google, чужой ключ там
  мешает. Поэтому `key` в репозитории обязателен (он закрепляет идентификатор локальной копии) и недопустим в архиве —
  скрипт это проверяет, не обходите проверку.
- В архив попадают только файлы из списка `$runtimeFiles` в `package.ps1`. Новый файл рантайма (например, ещё один
  скрипт) нужно добавить и туда, и в `manifest.json`, иначе он не уедет в стор.
- `dist/`, `.keys/`, `node_modules/` в git не попадают. Приватный ключ подписи — в `.keys/private.pem`; публичная часть
  уже в манифесте. Не публикуйте приватный ключ и не удаляйте `.keys/` из `.gitignore`.
- Теги релизов: `vMAJOR.MINOR.PATCH`. Опубликованные теги не переписываются — исправление оформляется новой версией.

### Приватность

- У расширения нет и не должно быть собственного сервера, аналитики, телеметрии и рекламы. Данные уходят только на
  сервер языковой модели, выбранный пользователем.
- API-ключи и резюме хранятся локально в `chrome.storage.local`. Ключ отправляется только его владельцу-провайдеру.
- Всё, что обрабатывает расширение, описано в `PRIVACY.md`. При добавлении новых данных (например, ещё одного поля
  профиля) политика обновляется в том же коммите — и в русской, и в английской части.
- Права в манифесте расширяются только при необходимости, каждое — с обоснованием в `store/review-answers.md`.

### Работа на hh.ru

- Разметка hh.ru меняется и требует авторизации, поэтому автоматически её проверить нельзя. Хрупкие места:
  - `SELECTORS` в `content.js` — вакансия, ссылки отклика, поле сопроводительного письма;
  - `RESUME_LINK_SELECTORS`, `RESUME_TITLE_SELECTORS` и список селекторов имени в `extractHhPage` (`background.js`).
  Для каждого элемента держите несколько запасных вариантов, а не один селектор.
- `extractHhPage` выполняется в контексте вкладки через `chrome.scripting.executeScript`. Функция **обязана быть
  самодостаточной**: никаких ссылок на переменные модуля, только аргументы и глобальные объекты страницы. Иначе она
  молча упадёт в браузере, а тесты этого не заметят.
- Резюме для разбора выбирается строго по точному совпадению адреса: подставлять резюме из случайной открытой вкладки
  нельзя.
- Панель живёт в shadow DOM и не должна ломать вёрстку страницы. Пользовательские данные выводятся через `textContent`,
  не через `innerHTML`.
- Отклик отправляет только пользователь. Любая автоматизация отправки — запрещена.

### Обмен сообщениями

- Все обращения к фоновой части идут через `MESSAGE_HANDLERS` в `background.js`. Новый тип сообщения добавляется туда;
  слушатель централизованно возвращает `true` и всегда отвечает — даже при внутренней ошибке, чтобы интерфейс не получал
  `undefined` вместо ответа.
- Стриминг генерации идёт через порт `llm`: сообщения `delta`, `reasoning`, `done`, `error`. Состояние готовности
  интерфейс получает обработчиком `status`, а не чтением настроек напрямую.
- Настройки имеют единый вид (`DEFAULT_SETTINGS`). Новое поле добавляется в `DEFAULT_SETTINGS`, в UI и, если оно
  относится к провайдеру, — в структуры `apiKeys` / `modelsByProvider`. Миграции старых значений описывайте в
  `loadSettings`.

### Промпт

- Правила промпта — часть продукта, а не текст «на подумать». Нельзя ослаблять запрет на выдуманные факты, на штампы
  и на места для ручной подстановки (`[Ваше имя]`, `{{company}}`, «Имя Фамилия»).
- Имя для подписи передаётся отдельным блоком. Если имя неизвестно, модель не придумывает его и подписывает письмо
  без имени — но без заглушек. Это поведение покрыто проверками, не ломайте его.
- Размышляющие модели тратят лимит токенов и на рассуждения: для них лимит поднимается, а `temperature` не
  отправляется. Различия провайдеров (`tokenParam`, `temperature`, поля рассуждений) задаются в каталоге `PROVIDERS`,
  а не в коде запроса.

## Как проверять изменения

- `npm test` — обязательно после правок `extractHhPage` и связанных селекторов. Проверки вырезают функцию из
  `background.js` и выполняют на подготовленных страницах, включая случай со служебной ссылкой «создать резюме».
- Логику фоновой части проверяйте стендом: `chrome.*` и `fetch` подменяются заглушками, затем вызываются обработчики
  из `MESSAGE_HANDLERS` и порт `llm`. Так проверяются сохранение настроек, авто-подгрузка резюме и текст ошибок.
  Временные стенды в репозиторий не коммитьте.
- `node --check` для классических скриптов (`content.js`, `popup.js`) и через копию с расширением `.mjs` для модулей
  (`lib.js`, `background.js`, `options.js`) — быстрый способ поймать синтаксис.
- `.\package.ps1` должна завершаться кодом 0 и печатать `homepage_url`; в архиве `manifest.json` лежит в корне и поля
  `key` нет.
- Живой hh.ru проверить нельзя (капча и авторизация). Если пользователь сообщает, что что-то не подтянулось,
  просите сохранённый HTML страницы и правьте селекторы по фактической разметке, а не наугад.

## Чего не делать

- Не добавлять зависимости рантайма: расширение должно собираться из файлов репозитория без сборщика.
- Не переписывать опубликованные теги и не делать force-push в `main`.
- Не использовать `git push --mirror`: в репозитории есть служебные ссылки редактора (`refs/agents/…`), которым в
  публичном репозитории не место.
- Не трогать `store/checklist.md` как обязательный документ для агента: это рабочий список пользователя, отмечайте
  пункты только по факту сделанного.
- Не описывать в документации несуществующие возможности: витрина и политика должны соответствовать коду.
