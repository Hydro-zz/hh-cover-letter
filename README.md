# HH Cover Letter

Расширение для Chrome (Manifest V3): на странице вакансии hh.ru появляется кнопка, которая читает текст вакансии,
сравнивает его с вашим резюме и пишет сопроводительное письмо под эту вакансию через языковую модель.
Дальше письмо можно поправить и вставить прямо в форму отклика одним нажатием.

Расширение **никогда не отправляет отклик само** — только заполняет поле письма, отправку делаете вы.

- Лицензия: [MIT](./LICENSE)
- Политика конфиденциальности: [PRIVACY.md](./PRIVACY.md)
- История версий: [CHANGELOG.md](./CHANGELOG.md)
- Публикация в Chrome Web Store: [store/checklist.md](./store/checklist.md)

## Установка

**Из Chrome Web Store** (после публикации): откройте страницу расширения и нажмите «Установить». Папку выбирать
не нужно: Chrome сам разместит файлы в профиле браузера
(`%LOCALAPPDATA%\Google\Chrome\User Data\<Профиль>\Extensions\<id>\<версия>_0\`) и будет обновлять их автоматически.

**В режиме разработки:**

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика» (переключатель в правом верхнем углу).
3. Нажмите «Загрузить распакованное расширение» и выберите папку с проектом.
4. Иконка расширения появится на панели Chrome (можно закрепить её через «Расширения»).

После правок кода достаточно нажать кнопку обновления (⟳) на карточке расширения в `chrome://extensions` и обновить
вкладку hh.ru. Версия на карточке должна совпадать с `version` в [manifest.json](./manifest.json) — если цифра старая,
значит Chrome ещё не подхватил свежие файлы. То же самое можно сделать из настроек кнопкой «Перезагрузить расширение».

Идентификатор расширения в режиме разработки закреплён публичным ключом в манифесте, поэтому переносы папки и
обновления кода не сбрасывают настройки. Идентификатор магазинной копии другой — это нормально, но означает, что
локальная и магазинная копии хранят настройки раздельно.

## Настройка

Откройте настройки одним из способов: иконка расширения → «Настройки», либо правый клик по иконке → «Параметры»,
либо кнопка «Настройки» в панели на странице вакансии.

1. **Провайдер и модель.** В списке «Провайдер» выберите сервис (по умолчанию DeepSeek), при необходимости впишите
   название модели — поле подсказывает типовые, но принимает любое своё значение. Ключ создаётся по ссылке из
   подсказки под полем ключа и вставляется в «API-ключ». Ключи хранятся **отдельно для каждого провайдера**, так что
   при переключении ничего не теряется.
2. **Резюме и имя.** Укажите ссылку на **страницу профиля** (или на конкретное резюме) и нажмите «Загрузить».
   Со страницы профиля расширение возьмёт ваше имя, названия и адреса всех резюме, а затем **прочитает текст каждого
   из них** — у каждого резюме он свой. В списке «Резюме для писем» выберите, какое подставлять в письма по умолчанию,
   и правьте его текст прямо в поле ниже: правки сохраняются именно в выбранное резюме. Если какое-то резюме не
   прочиталось, нажмите «Перечитать» или вставьте текст вручную. Имя из профиля попадёт в поле «Имя и фамилия для
   подписи» и будет использовано в подписи письма — подставлять его вручную не придётся.
3. **Стиль.** Тон (деловой / дружелюбный / коротко и по делу / …), объём, язык и дополнительные пожелания
   (например, «подчеркни опыт с Kafka», «не упоминай зарплату»).
4. Кнопка «Проверить подключение» делает минимальный запрос к выбранному провайдеру и подтверждает, что ключ
   и модель работают. Под кнопками есть строка диагностики: версия расширения, провайдер, эндпоинт, наличие ключа
   и резюме.

## Провайдеры

Все провайдеры общаются по одному протоколу — OpenAI-совместимому Chat Completions
(`POST {baseUrl}/chat/completions`), поэтому отличается только обвязка. Встроенные варианты:

| Провайдер | Базовый адрес | Ключ |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | нужен |
| OpenAI | `https://api.openai.com/v1` | нужен |
| OpenRouter | `https://openrouter.ai/api/v1` | нужен |
| Groq | `https://api.groq.com/openai/v1` | нужен |
| Mistral | `https://api.mistral.ai/v1` | нужен |
| Google Gemini (OpenAI-совместимый) | `https://generativelanguage.googleapis.com/v1beta/openai` | нужен |
| Ollama | `http://localhost:11434/v1` | не нужен |
| LM Studio | `http://localhost:1234/v1` | не нужен |
| Свой OpenAI-совместимый сервер | задаёте сами | нужен |

Что расширение подстраивает под провайдера автоматически:

- **Имя параметра лимита.** DeepSeek, Groq, Mistral, OpenRouter и локальные серверы получают `max_tokens`,
  OpenAI — `max_completion_tokens`, иначе новые модели OpenAI отказывают.
- **Температуру.** Не отправляется ни для `reasoner`, ни для провайдеров вроде OpenAI, где часть моделей принимает
  только значение по умолчанию. Ползунок в настройках при этом отключается с пояснением.
- **Поле рассуждений.** DeepSeek присылает `reasoning_content`, OpenRouter — `reasoning`; оба варианта читаются.

### Свой сервер

Выберите «Свой OpenAI-совместимый сервер», укажите адрес вида `https://host/v1` и нажмите «Разрешить доступ
к домену» — браузер спросит подтверждение, потому что произвольный домен нельзя прописать в манифесте заранее.
Без этого разрешения запрос заблокируется. Всё остальное работает так же: ключ, модель, проверка подключения.

Подходит для любого сервиса с OpenAI-совместимым API — vLLM, llama.cpp server, Together, Fireworks, DeepInfra,
Yandex/облачных шлюзов и т. п. Если у сервиса свой протокол (например, нативный Anthropic), он не подойдёт без
отдельного адаптера: формат запроса и SSE-событий там другой.

## Использование

1. Откройте вакансию на hh.ru (`hh.ru/vacancy/…`).
2. В правом нижнем углу нажмите «✍ Письмо под вакансию» (или `Alt` + `Shift` + `C`). В панели виден список резюме:
   по умолчанию выбрано то, что задано в настройках, но для этой вакансии можно взять другое — выбор запомнится
   для неё и не повлияет на остальные.
3. «Сгенерировать» — текст печатается в поле на глазах, его можно сразу править.
4. «Вставить в отклик» — расширение открывает форму отклика и подставляет письмо.
   Если оно не подставилось, нажмите «Копировать» и вставьте вручную (`Ctrl` + `V`).
5. Отправьте отклик сами. «Перегенерировать» даёт другой вариант, «Настройки» открывают страницу параметров.

## Приватность

- Ключи (отдельно по провайдерам) и текст резюме хранятся локально: `chrome.storage.local` вашего профиля Chrome.
- При генерации на сервер выбранного провайдера уходят только текст вакансии, текст резюме и ваши пожелания к стилю.
  Ничего больше не собирается и никуда не отправляется.
- Ключ не попадает в код страницы hh.ru: запрос делает фоновый service worker расширения.
- Разрешения выданы узко: `hh.ru` для чтения вакансии и резюме, домены перечисленных провайдеров для запросов.
  Для своего сервера разрешение запрашивается отдельно и только по кнопке.

## Стоимость

Запросы идут на ваш аккаунт у выбранного провайдера по его тарифам. Одно письмо — это несколько тысяч входных токенов
и до ~1.4k выходных, то есть доли цента на недорогих моделях. Размышляющие модели (например, `deepseek-reasoner`)
дороже: оплачиваются и токены рассуждений. Локальные Ollama и LM Studio бесплатны — платите только за электричество.

## Выбор модели

| Тип модели | Особенности в расширении |
| --- | --- |
| Обычные (`deepseek-chat`, `gpt-4o-mini`, локальные) | Лимит токенов по умолчанию — 1400, хватает с запасом. «Температура» применяется, если провайдер её поддерживает |
| «Размышляющие» (`deepseek-reasoner`, o-series, gpt-5) | Сначала рассуждают, потом пишут письмо. **Лимит токенов покрывает и рассуждения, и текст письма**, поэтому расширение поднимает его минимум до 8000 — при малом лимите модель тратит всё на размышления, и письмо приходит пустым. «Температура» таким моделям не отправляется. Во время генерации панель показывает, сколько знаков размышлений уже готово, — это нормальный ход работы, а не зависание |

Если ответ всё же обрывается, увеличьте «Максимум токенов»; панель в этом случае предупредит, что текст недописан.
Размышляющие модели заметно дороже обычных: оплачиваются и токены рассуждений.

## Ограничения и нюансы

- **Разметка hh.ru меняется.** Расширение ищет элементы по атрибутам `data-qa` (например,
  `[data-qa="vacancy-description"]`, `[data-qa="vacancy-response-link-top"]`). Если hh.ru переедет на новые атрибуты,
  письмо может не считаться или не вставляться. Что править: объект `SELECTORS` в [content.js](./content.js) —
  там для каждого элемента список селекторов-запасных вариантов.
- Если панель пишет «текст вакансии не прочитан», откройте консоль страницы (<kbd>F12</kbd>) — расширение не
  шумит в консоль, но по элементу `data-qa="vacancy-description"` в инспекторе видно актуальный атрибут.
- Письмо — черновик. Модель опирается только на резюме, но всё равно вычитывайте текст: неверные акценты
  и формулировки случаются.
- Сайты-агрегаторы и другие job-борды (не hh.ru) не поддерживаются: `host_permissions` ограничены hh.ru.
- Поддерживаются только OpenAI-совместимые API. Нативные протоколы (Anthropic Messages API, Gemini `generateContent`)
  требуют отдельного адаптера — их форматы запроса и SSE-событий отличаются.
- Список типовых моделей в подсказках — снимок на момент написания. Он не обновляется автоматически: если модель
  переименовали или появилась новая, просто впишите её название в поле вручную.

| `test/` | Проверки: разбор разметки hh.ru на jsdom и фоновая логика с заглушками Chrome (запуск: `npm test`) |
| `package.ps1` | Сборка релизного ZIP для Chrome Web Store |
| `store/` | Тексты витрины, обоснование разрешений, чек-лист публикации |
| `PRIVACY.md` | Политика конфиденциальности (RU + EN) |
| `CHANGELOG.md` | История версий в формате Keep a Changelog |

## Разработка и релизы

Сборка релиза:

```powershell
.\package.ps1                      # соберёт dist/hh-cover-letter-<версия>.zip
.\package.ps1 -HomepageUrl https://github.com/user/repo
```

Скрипт откажется собирать архив, если версия манифеста не описана в [CHANGELOG.md](./CHANGELOG.md), отсутствует
обязательный файл, нет иконки нужного размера или в манифесте остались заглушки. Он также сверяет структуру релизного
манифеста с исходным, чтобы текстовые правки не портили JSON. Поле `key` из релизного манифеста вырезается: в магазине
идентификатор выдаёт Google, и чужой ключ там только помешает. Ссылка на сайт проекта подставляется из `git remote origin`,
поэтому достаточно один раз настроить remote.

Порядок выпуска новой версии: изменить код → поднять `version` в манифесте → добавить запись в changelog с тем же
номером → `.\package.ps1` → загрузить архив в кабинет разработчика. Полный список шагов, включая скриншоты и поля
витрины, — в [store/checklist.md](./store/checklist.md).

Приватный ключ в `.keys/` игнорируется git. Публичная часть уже в манифесте; если файл потерять, идентификатор
локальной копии всё равно не изменится, а вот подписывать собственные `.crx` будет нечем — держите бэкап.

## Проверки

Разбор разметки hh.ru — самая хрупкая часть расширения, поэтому он покрыт проверками на настоящем DOM (jsdom):

```powershell
npm install     # один раз, нужен только для проверок
npm test
```

Проверки вырезают функцию разбора из [background.js](./background.js) и выполняют её на подготовленных страницах:
карточки резюме с служебной ссылкой «создать резюме», запасной путь без карточек, название рядом со ссылкой, общий
контейнер списка (чужой заголовок не должен подставляться) и страница конкретного резюме. Исходники проверок
и `node_modules` в сборку расширения не входят: `package.ps1` упаковывает только файлы, перечисленные в списке
`$runtimeFiles`.

| Файл | Что проверяет |
| --- | --- |
| `test/extract.test.cjs` | Разбор разметки страницы профиля и резюме (jsdom) |
| `test/background.test.cjs` | Фоновая логика: миграция настроек, чтение всех резюме, выбор под вакансию, генерация (Chrome подменяется заглушками) |
| `test/options.test.cjs` | Страница настроек: у каждого резюме свой текст, «Перечитать» заменяет текст, переключение не переносит текст между резюме |
| `test/panel.test.cjs` | Панель на странице вакансии: список резюме, передача выбора в генерацию |

При правках разметки настроек или панели запускайте проверки до коммита: именно они ловят такие ошибки, как перенос
текста резюме в чужое резюме.

## Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| «Модель израсходовала лимит токенов на рассуждения» | `deepseek-reasoner` потратил весь лимит на размышления: увеличьте «Максимум токенов» (для reasoner действует минимум 8000) или выберите `deepseek-chat` |
| «Готово, но ответ оборван лимитом токенов» | Письмо недописано: увеличьте «Максимум токенов» и перегенерируйте |
| «Модель вернула пустой ответ» | Повторите запрос; если повторяется на размышляющей модели — увеличьте «Максимум токенов» |
| «Фоновая часть расширения не ответила» / страница настроек молчит после нажатия кнопки | В Chrome работает service worker от старой версии файлов: нажмите «Перезагрузить расширение» в настройках либо ⟳ на карточке в `chrome://extensions`, затем обновите страницу настроек. Строка диагностики под кнопками покажет версию и список доступных операций |
| «Не задан API-ключ <провайдер>» | Ключ для выбранного провайдера не сохранён: настройки → «API-ключ» → «Сохранить». Ключи хранятся по провайдерам, при переключении вводите ключ заново |
| «<провайдер> не принял API-ключ (401)» | Ключ скопирован не полностью, отозван или принадлежит другому сервису |
| «Закончились средства (402)» / «исчерпана квота (429)» | Пополните баланс или проверьте тариф у выбранного провайдера |
| «не нашёл эндпоинт или модель (404)» | Опечатка в названии модели или в адресе сервера: сверьте и то и другое |
| «Не удалось связаться с <host>» на своём сервере | Нажмите «Разрешить доступ к домену» в настройках: без разрешения браузер блокирует запрос к произвольному домену |
| «Не указан адрес своего сервера» | Для провайдера «Свой OpenAI-совместимый сервер» заполните поле адреса, например `https://host/v1` |
| «Не заполнено резюме» | В настройках не загружено ни одного резюме: укажите ссылку на профиль или резюме и нажмите «Загрузить» |
| «Текст выбранного резюме не прочитан» | Нажмите «Перечитать» в настройках или вставьте текст вручную; при генерации расширение попробует прочитать резюме само |
| В письме осталось место для имени («[Ваше имя]») | Заполните «Имя и фамилия для подписи» в настройках — имя подставляется в подпись автоматически |
| В панели нет списка резюме | В настройках не загружены резюме; после загрузки профиля список появится сам |
| «На странице не нашлось ссылок на резюме» | Ссылка ведёт не на вашу страницу профиля или вы не авторизованы на hh.ru; вставьте прямую ссылку на резюме |
| «Не удалось прочитать текст резюме» | Ссылка ведёт не на ваше резюме или резюме скрыто; откройте резюме под своим аккаунтом и нажмите «Загрузить резюме» снова |
| «Не нашёл поле сопроводительного письма» | Откройте форму отклика вручную, нажмите «Копировать» и вставьте текст |
| Панель не появилась | Обновите вкладку (F5); убедитесь, что страница — `hh.ru/vacancy/…`; проверьте, что расширение включено |
| Кнопка в popup неактивна | Нужны ключ, резюме (текст или ссылка) и открытая вкладка вакансии hh.ru |
| Расширение молчит после правок кода | Service worker не перезапустился: ⟳ в `chrome://extensions` или «Перезагрузить расширение» в настройках |
