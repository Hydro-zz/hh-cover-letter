# Чек-лист релиза в Chrome Web Store

Порядок важен: часть шагов влияет на то, что попадёт в архив, поэтому лучше идти сверху вниз.

## 0. Сделать прямо сейчас: локальная копия сменила идентификатор

В 1.0.0 в манифест добавлен публичный ключ, а идентификатор распакованного расширения Chrome выводит из ключа, а не
из пути. Значит:

- [ ] В `chrome://extensions` нажать ⟳ на карточке «HH Cover Letter». Версия должна стать **1.0.0**.
- [ ] Если появилась вторая карточка с тем же именем — старую (ошибочную, с прежним идентификатором) удалить.
- [ ] Ввести API-ключ заново и нажать «Загрузить резюме»: настройки прежней копии остались под старым идентификатором.
- [ ] Дальше идентификатор больше не меняется: переносы папки и обновления кода настройки не сбросят.

Ожидаемый идентификатор локальной копии: `jilifogjebkjlekmchcgnhagalbgaiog` (лежит в `.keys/extension-id.txt`).

## 2. Публичный URL политики конфиденциальности

Кабинет разработчика требует ссылку, открывающуюся в браузере. Репозиторий публичный, поэтому рабочая ссылка уже есть:

```
https://github.com/Hydro-zz/hh-cover-letter/blob/main/PRIVACY.md
```

- [ ] Открыть её в приватном окне и убедиться, что страница видна без авторизации.
- [ ] По желанию: включить GitHub Pages (Settings → Pages → Deploy from branch → `main` / root) и получить адрес
      вида `https://hydro-zz.github.io/hh-cover-letter/PRIVACY` — выглядит опрятнее, чем страница на github.com.

## 3. Скриншоты

Нужно 1–5 штук, ровно 1280×800 или 640×400 пикселей. Снять в браузере на реальном интерфейсе (макеты не принимают).
Удобнее всего расширением для скриншотов окна фиксированного размера или инструментом разработчика в режиме
адаптивной вёрстки: `Ctrl+Shift+M`, задать 1280×800.

- [ ] **Кадр 1.** Страница вакансии hh.ru, открыта панель, виден заголовок вакансии и кнопка «Сгенерировать».
- [ ] **Кадр 2.** Генерация в процессе: печатается текст, в статусе «Генерирую письмо…».
- [ ] **Кадр 3.** Письмо вставлено в форму отклика: поле заполнено, кнопка «Отправить» **не** нажата.
- [ ] **Кадр 4.** Настройки, блок «Провайдер и модель»: раскрыт список провайдеров, видны подсказки моделей.
- [ ] **Кадр 5.** Настройки, блок «Резюме»: ссылка на резюме и загруженный текст.

Совет: на кадрах не должно быть вашего API-ключа, персональных данных третьих лиц и лишних вкладок. Текст резюме
на кадре 5 лучше взять демонстрационный.

## 6. Сборка релиза

- [ ] Убедиться, что версия в [manifest.json](../manifest.json) совпадает с верхней записью в [CHANGELOG.md](../CHANGELOG.md).
- [ ] Собрать архив: `.\package.ps1`
- [ ] Проверить вывод: `manifest.json` в корне архива, размер и список файлов. Скрипт сам откажется собирать, если
      версии нет в changelog, отсутствует обязательный файл или в манифесте остались заглушки.
- [ ] Результат: `dist/hh-cover-letter-1.0.0.zip`.

## 7. Подача

- [ ] В кабинете: «Новый элемент» → загрузить `dist/hh-cover-letter-1.0.0.zip`.
- [ ] Заполнить витрину текстами из [listing.md](./listing.md): название, краткое и подробное описание, категория,
      язык, скриншоты.
- [ ] Вкладка «Практики конфиденциальности»: заполнить по [review-answers.md](./review-answers.md), указать URL политики.
- [ ] Вкладка «Обоснование разрешений»: вставить таблицу обоснований оттуда же.
- [ ] Ответить на вопрос о целях использования данных (единственная функция — генерация письма).
- [ ] Отправить на проверку. Обычно это от нескольких часов до нескольких дней; при запросе дополнительных сведений
      письмо приходит на почту издателя.

## 8. После публикации

- [ ] Установить расширение из стора и пройти путь целиком: ключ → резюме → генерация → вставка в отклик.
- [ ] Помнить, что идентификатор магазинной копии отличается от локального, поэтому настройки вводятся заново.
      Локальную распакованную копию можно оставить, но две копии сразу путают: лучше отключить одну.
- [x] Тег `v1.0.0` создан и отправлен в репозиторий.
- [ ] Оформить релиз на странице тега (<https://github.com/Hydro-zz/hh-cover-letter/releases/new?tag=v1.0.0>),
      вставив текст записи 1.0.0 из [CHANGELOG.md](../CHANGELOG.md).
- [ ] Ссылку на витрину добавить в [README.md](../README.md).

## 9. Обновления

Порядок для каждой следующей версии:

1. Внести изменения в код.
2. Поднять `version` в [manifest.json](../manifest.json).
3. Добавить запись в [CHANGELOG.md](../CHANGELOG.md) с тем же номером.
4. Собрать: `.\package.ps1`
5. В кабинете: «Обновить элемент» → загрузить новый архив → отправить на проверку.

## Отдельно: донаты

Оплату через Chrome Web Store Google отключил, а платёжные формы внутри расширения вызывают вопросы на ревью.
Безопасный вариант, если решите добавить: ссылка на сервис донатов (Boosty, Buy Me a Coffee, ЮMoney) в описании витрины
и в README. Внутри интерфейса лучше не размещать призывы к оплате.
